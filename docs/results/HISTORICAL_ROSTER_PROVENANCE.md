# HISTORICAL ROSTER — preservation record

The pre-canonical Arena roster was **live-discovered** by `tools/build_roster.gd`
against whatever LM Studio held at the time. It is machine-specific, so repo
policy (`.gitignore:74`) deliberately does not ship it.

Policy says do not track the artifact. It does not say forget it existed. An
ignored `.bak` is a local convenience that a disk cleanup, a fresh clone, or a
different machine erases without trace. This record is tracked so the artifact
stays private and the *fact of it* stays auditable.

---

## Composition, which is the part worth keeping

```text
agent-01  Stablelm 2 Zephyr #1   stablelm-2-zephyr-1.6b
agent-02  Stablelm 2 Zephyr #2   stablelm-2-zephyr-1.6b
agent-03  H 2o Danube 3 4B #1    h2o-danube3-4b-chat
agent-04  H 2o Danube 3 4B #2    h2o-danube3-4b-chat
agent-05  Gemma 3 1B             gemma-3-1b-it-fast-guff

3 distinct species, 5 agents: 2 + 2 + 1
```

**That is not the canonical roster's shape, and the difference is scientific,
not cosmetic.** Every result produced under this roster came from a
*3-species + duplicate-instances* population. The canonical roster is
*5 species × 1 instance*. Those are two different points in exactly the design
space reserved as a future manipulation:

```text
5 distinct species            <- canonical roster, from 2026-09-08
3 species + duplicates        <- THIS roster, and every result under it
1 species x 5 instances       <- never run
```

Any comparison across that boundary is a comparison across a changed population,
not a changed condition. Results collected under this roster must say so.

That rule is frozen as **REGIME A** in `POPULATION_REGIMES.md`.

## Honesty note — what is and is not proven about these bytes

```text
EVIDENCE CLASS:  OBSERVED_SHAPE (a verbatim in-session read of the file)
WITNESS:         the full file contents were printed and read before the
                 overwrite, and the .bak was reconstructed from that read
```

Two limitations, stated rather than papered over:

1. **`captured_at` is UNKNOWN.** The original file's mtime was destroyed when
   the canonical generator overwrote it. The `.bak`'s mtime is when the
   reconstruction was written, which is not the same fact and must not be
   quoted as one.

2. **The sha256 is of the RECONSTRUCTION, not provably of the original.** The
   content came from a verbatim read, but byte-identity is **UNVERIFIED**:
   trailing-newline and whitespace details could differ from what
   `JSON.stringify(doc, "\t")` originally emitted. The *semantic* content —
   agents, model keys, personas, colors, runtime — is faithful. The hash is
   therefore a fingerprint of the preserved copy, useful for detecting drift in
   the `.bak` from here forward, and **not** a proof of what was on disk before.

The overwrite is the underlying mistake: it happened before the value of the
prior bytes was considered. Recorded here rather than smoothed over, since a
preservation record that overstates its own provenance is worse than none.

## If the local copy is gone

It cannot be regenerated. `build_roster.gd` re-discovers against the models
installed *now*, which is a different question with a different answer. The
composition table above is then the surviving record, and it is enough to
interpret any result collected under that roster.
